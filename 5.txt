To implement a **19-point Laplacian stencil** in GLSL (commonly known as the **Patra–Karttunen isotropic stencil**), we extend beyond simple orthogonal grid sampling to include diagonal edge neighbors in 3D space [1-3].

Compared to standard 6-point 3D stencils, the 19-point stencil minimizes anisotropic discretization errors, preventing expanding bacterial tendrils, spirals, and droplets from unnaturally distorting or aligning with coordinate grid axes [2].

---

### 1. Mathematical Weights & Zero-Sum Principle

The 19-point Patra–Karttunen stencil evaluates:
* **1 Center Cell**: Weight = **\\(-4.0\\)**
* **6 Face Neighbors** (at distance \\(r = 1\\)): Weight = **\\(+1/3\\)** (\\(\approx +0.3333\\))
* **12 Edge Neighbors** (at distance \\(r = \sqrt{2}\\)): Weight = **\\(+1/6\\)** (\\(\approx +0.1667\\))

The Laplacian formula is discretized as [3]:
\\[\nabla^2 f \approx \frac{1}{h^2} \left( \frac{1}{3} \sum_{\text{face}} f + \frac{1}{6} \sum_{\text{edge}} f - 4.0 \cdot f_{\text{center}} \right)\\]

This satisfies the zero-sum constraint (\\(6 \times \frac{1}{3} + 12 \times \frac{1}{6} - 4.0 = 0\\)), guaranteeing no spurious creation or loss of mass during diffusion [4, 5].

---

### 2. GLSL Compute Shader Implementation (3D Volume)

In a GLSL 3D compute shader or fragment pass operating on a `sampler3D` texture, the 19-point stencil can be implemented as follows [1, 2]:

```glsl
// =============================================================================
// 19-Point Isotropic Patra-Karttunen Laplacian Stencil (GLSL)
// =============================================================================
vec4 laplacian19(ivec3 p, sampler3D u_src) {
    // 1. Fetch Central Cell
    vec4 center = texelFetch(u_src, p, 0);

    // 2. Sum 6 Face Neighbors (distance = 1)
    vec4 face_sum = vec4(0.0);
    face_sum += texelFetch(u_src, p + ivec3( 1,  0,  0), 0);
    face_sum += texelFetch(u_src, p + ivec3(-1,  0,  0), 0);
    face_sum += texelFetch(u_src, p + ivec3( 0,  1,  0), 0);
    face_sum += texelFetch(u_src, p + ivec3( 0, -1,  0), 0);
    face_sum += texelFetch(u_src, p + ivec3( 0,  0,  1), 0);
    face_sum += texelFetch(u_src, p + ivec3( 0,  0, -1), 0);

    // 3. Sum 12 Edge Neighbors (distance = sqrt(2))
    vec4 edge_sum = vec4(0.0);
    // XY-Plane Edges
    edge_sum += texelFetch(u_src, p + ivec3( 1,  1,  0), 0);
    edge_sum += texelFetch(u_src, p + ivec3(-1,  1,  0), 0);
    edge_sum += texelFetch(u_src, p + ivec3( 1, -1,  0), 0);
    edge_sum += texelFetch(u_src, p + ivec3(-1, -1,  0), 0);
    // XZ-Plane Edges
    edge_sum += texelFetch(u_src, p + ivec3( 1,  0,  1), 0);
    edge_sum += texelFetch(u_src, p + ivec3(-1,  0,  1), 0);
    edge_sum += texelFetch(u_src, p + ivec3( 1,  0, -1), 0);
    edge_sum += texelFetch(u_src, p + ivec3(-1,  0, -1), 0);
    // YZ-Plane Edges
    edge_sum += texelFetch(u_src, p + ivec3( 0,  1,  1), 0);
    edge_sum += texelFetch(u_src, p + ivec3( 0, -1,  1), 0);
    edge_sum += texelFetch(u_src, p + ivec3( 0,  1, -1), 0);
    edge_sum += texelFetch(u_src, p + ivec3( 0, -1, -1), 0);

    // 4. Combine with Patra-Karttunen Isotropic Weights
    return (1.0 / 3.0) * face_sum + (1.0 / 6.0) * edge_sum - 4.0 * center;
}
```

---

### 3. Key Shader Optimization Considerations

* **Texel Offsets**: Using `texelFetch` with integer coordinates (`ivec3`) avoids floating-point precision issues and handles boundary conditions efficiently if `GL_REPEAT` or `GL_CLAMP_TO_EDGE` is active [6, 7].
* **Shared Memory Tiling**: If you are using GLSL compute shaders with 3D workgroups (e.g., \\(8 \times 8 \times 8\\)), caching neighboring texels into `shared` memory reduces texture bandwidth bottlenecks across neighboring threads [1, 2].
